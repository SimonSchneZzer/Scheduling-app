# Task Specs

Use this folder for short implementation specs before building meaningful features.

Create one Markdown file per feature or vertical slice. Keep specs short and update them as the feature changes.

Recommended structure:

```md
# Task: Short Name

## Goal

What should exist after this task is done?

## Non-Goals

What should explicitly not be included?

## User Flow

How should a user experience this feature?

## Data Model Impact

What entities, fields, or migrations are needed?

## API Impact

What endpoints, actions, or server functions are needed?

## Scheduling Engine Impact

What constraints, scoring, candidate generation, or explanations change?

## Tests

What should be tested?

## Open Questions

What needs a decision before or during implementation?
```
